# dsh-client-ui-settings-skills

[English](README.md) | 中文

**技能**设置分区：当前会话所在项目能发现的全部技能，按来源分组，并给出每个技能可被用户覆盖的两个调用面。这是 `skill.inventory` 与 `skills` settings 命名空间之上的策略编辑器——不是 Cordis Loader 清单，后者属于**插件**分区。

## 这里显示什么

技能发现以会话的工作目录为范围，因此本页由当前会话寻址，并说明它读取的是哪个目录。没有当前会话时无从寻址，本页会如实说明，而不是列出一份陈旧的项目清单。

分组按由近及远排列：先是该范围自身的链路，再是宿主全局层；同层内先好后差。每组以其来源为标题——项目与用户的 `.dsh` / `.agents` / `.claude` 根、配置的目录、随部署分发的技能，以及运行时贡献——并展示它被发现的目录，POSIX 家目录缩写为 `~`。来源词汇由 Host 拥有且保持开放，因此本包不认识的取值按原样渲染，而不是套上一个错误的标签。

每一项被发现的贡献都会出现，包括已被更近定义遮蔽的落败者。被遮蔽的行为只读：对它设置覆盖，寻址的是一个已被他人占用的名字。若答案不完整——某个提供方失败，或目录在发现过程中发生变化——本页会就地说明，而不是把自己当作完整列表呈现。

## 写入

每行带两个开关，**模型**与**用户**，显示 Host 解析出的生效策略。翻动其中一个会把该调用面作为这个技能名的覆盖存下来，并原样保留另一个调用面，因为两者共用同一条存储条目。带有存储覆盖的行会被标注，并提供清除该条目的重置入口，恢复技能自身声明的策略。

写入经由 `skills` 命名空间的客户端 settings scope，每次写入都用读到的 revision 设栅。本页不做乐观展示：写入落定后会重读清单，因此行上显示的始终是 Host 解析出的结果。它同样会在转发的 `skills/change` 失效通知与连接重置时重读，并在当前会话变动时重新寻址。设置文档只读、或不提供 `skills` 命名空间的部署，会禁用全部控件并说明原因。

## 模型体验

间接：本分区只存储调用覆盖，模型可见的技能目录与技能渲染出的正文由技能注册表与 `dsh-tool-skill` 拥有。

#### KV Cache 影响

无；该包既不组装也不发送提供方请求。

## 已知限制与暂缓事项

- **每个名字一条覆盖，而非每个贡献一条**——存储的分区以技能名为键，因为分层合并本就为每个名字解析出唯一赢家，所以同一技能的项目副本与用户副本无法分别治理；覆盖跟随当前胜出的那一个贡献。
- **范围属于会话，而非面板**——设置是根级界面，自身没有会话，因此本页跟随当前会话的工作目录。要查看另一个项目的技能，得先在那里打开一个会话。
- **没有搜索与批量操作**——发现了大量技能的部署只会得到一份长列表；过滤，以及一次性关掉整个来源，都要等真实清单的形态明确后再做。
- **被拒绝的写入只表现为行未发生变化**——scope 会为未能落地的写入重新加载 Host 状态，因此开关会退回存储的位置而不说明原因；本页报告读取失败，但不报告写入失败。
