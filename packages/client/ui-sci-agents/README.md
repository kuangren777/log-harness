# @deepseek-ai/dsh-client-ui-sci-agents

English | [中文](README.zh.md)

The CaMeL Science agent surface: the full-bleed 「智能体」 view — a roster of the personas the profile mounts, one persona's configuration, and one persona's delegation log — plus the rail button that routes to it. Two registrations into two seats this package does not own, ui-layout's keyed `view` and the [sci shell](../ui-sci-shell/README.md)'s `rail.item`, so composing it out of cordis.yml removes the view and the button together and leaves every other surface exactly as it was. Contract: the [slot system standard](../../../.agents/notes/implemented/architecture/2026-07-22-slot-type-chain-implementation.md).

The wire seam is `src/client/index.ts` alone, and it owns the whole namespace lifetime. `apply` mounts the host's generated Remote contribution itself — `ctx.remote.$mount(agentsRemote)`, awaited before any registration — because [`@deepseek-ai/dsh-api-remotes`](../../api/remotes/README.md) is the base assembly every profile boots and a science-only namespace does not belong in it. The mount's disposer rides an effect on this fiber, so composing the row out of cordis.yml takes the namespace with it. For the same reason `inject` names `remote` but **not** `remote.sci.agents`: a fiber that injects what its own apply provides never activates. The namespace is therefore read with `ctx.get('remote.sci.agents')` rather than `ctx.remote['sci.agents']` — the traceable-service proxy forwards that property read to a context property, and a context property resolves only for a fiber that injected it.

The injected face turns those envelopes into the plain records and total outcomes `src/client/contract.ts` declares, so no component ever sees an RPC error. A refused settings write arrives as a code, a namespace that is somehow not mounted arrives as `AGENTS_REMOTE_UNAVAILABLE`, a call that never reached an answer arrives as `AGENTS_REMOTE_FAILED`, and all three render as stated facts rather than as a throw inside an event handler.

Every number on screen is the host's. The subtitle counts the personas actually enabled and sums their real month delegations; a card's three tiles are that persona's month calls, its mean duration, and its output tokens, and a persona whose average or token total the host could not compute loses that tile rather than reading as a zero it never measured. The status pill is a fact about the log, not a guess — the load pass reads every persona's delegation log, so 「运行中」 means a call really is in flight, against 「待命」 for an enabled persona with none and 「已停用」 for one the settings turned off.

The configuration page offers only what the host would honour, which is also why it offers no reasoning-depth control. The base-model control is the host's catalog, one segmented group per provider, with the model in force pressed; a catalog that could not be read states that the agent follows the session model instead of offering an empty choice. The three permission switches map to the `toolFilter.deny` the host applies at `ctx.tools.restrict` time, and the enable switch names the tool a disabled persona would refuse. There is no save button, because there is nothing to save: every gesture writes immediately and the page redraws from the agent the host answers with, so a top indicator states where that write stands — including that it failed — rather than offering a control that would do nothing.

The delegation log is a way back into the research flow, not a read-only report: a row is focusable, answers Enter and Space as well as a click, and carries the whole reading in its accessible name. Activating one calls `ctx.sessions.open(sessionId)` and switches the frame to the conversation view, reopening the session that made that delegation. The token column exists only when at least one settlement carried usage, since a column of dashes would claim the host measures something it does not; a call still running says 「进行中」 instead of inventing a duration.

The store carries what the whole view agrees on — the page, the persona it is about, the roster, the logs read so far, the catalog, and where the last write stands — so a trip through the research flow and back finds the same roster rather than a loading one, and a refresh keeps the reader's place. A page about a persona the roster no longer carries falls back to the roster rather than to an empty frame. Styling is tokens only, in CSS Modules, so every surface follows the theme's light and dark alike; `CONVERSATION_VIEW` is the one symbol imported from ui-layout and is declared as a `dsh.client.external` module-graph request. The `/client` exports are the plugin body (`apply`/`inject`) alone.

## Model Experience

None, as this is a browser-side configuration surface whose Node half is an inert loader seat: it registers no tool, prompt section, or session event, and every fact it draws was computed by the `sci-agents` host package over `tool-subagent`'s settings sections and the `sci_audit` table, which own their own Model Experience.

#### KV Cache effect

None; this package neither assembles nor sends a provider request.

## Known Limitations and Deferred Work

- **The record types are still mirrored, not imported.** `src/client/contract.ts` restates the roster/call/catalog vocabulary of spec §2.3 and `src/client/index.ts` restates the four endpoint signatures over it, so a host-side field rename reaches this package as a wrong-looking card rather than as a type error. The mount imports the generated contribution as a value, which brings its declarations into this compilation, so switching both mirrors to `@deepseek-ai/dsh-sci-agents/types` is a mechanical follow-up rather than a blocked one.
- **The generated contribution is bundled, zod and all.** `lib/client.js` inlines the codecs the mount needs, the same shape and order of magnitude as the base `dsh-api-remotes` client artifact, which inlines its own. A profile that composes this row pays for one more copy of that runtime; sharing it would mean making the wire codecs a module-table row, which is a decision above this package.
- **There is no reasoning-depth control, and the contract carries no depth field.** Spec §3 sketched a three-way selector conditional on the model catalog declaring `reasoningEfforts`, and spec §2.1/§5 pre-authorized dropping it if `AgentOptions` could not carry an effort. It cannot: `AgentOptions` declares `provider`, `model`, and `maxTokens` only (`packages/core/agent/src/runtime-types.ts:24-31`), and the child loop restores a `reasoningEffort` solely from an existing session header (`packages/core/agent-loop/src/agent.ts:437-455`), which a fresh child does not have. A real passthrough would take edits in two core packages plus per-route validation, since effort ids are adapter-owned and opaque — `llm-deepseek` offers `off`/`low`/`high`/`max`, which the spec's `low|medium|high` union cannot name. So `sci-agents` omits the field from the wire and this package omits it from `contract.ts` and the UI, rather than declaring a control that would write a value reaching nothing.
- **A partly unreadable model catalog is shown as a shorter list, not as a warning.** `models()` also answers with the providers whose catalog lookup failed, and this face drops that half: the segmented control offers the providers that answered and says nothing about the ones that did not. Only a catalog that is empty outright produces a stated message. Surfacing per-provider failures is a control the design reference does not draw, so it is deferred rather than invented here.
- **The roster is read once per mount, and never pushed.** Settings and audit rows both change on the host — another tab's configuration write, or a delegation finishing while this view is open — and nothing tells this view about either. Reopening the view re-reads everything; there is no subscription, because the `sci.agents` namespace publishes no events (spec §2.3).
- **A persona's status pill costs one log read each.** The load pass calls `calls()` once per persona to learn whether any delegation is in flight, so a six-persona roster makes seven round trips on open. A `running` count on the roster payload would collapse them, but that is a host-side field this release does not add.
- **The three permission switches are the only tool control offered.** The host's `toolFilter` takes arbitrary allow and deny lists; this page writes the three groups the spec names (web, sandboxed code, knowledge-base writes) and cannot express a per-tool exception. A persona configured with a hand-written filter outside those groups shows up here only as whichever of the three switches its deny list implies.
- **Token totals depend on what the settlement carried.** `monthTokens` and a row's `outputTokens` exist only when usage reached the audit record, so the tile and the column appear for some personas and not others; that unevenness is the host's measurement, not a rendering choice, and this view states the absence rather than filling it with a zero.
- **The retrieval column appears only when a child's log was readable.** `retrievalCalls` / `retrievalRepeats` come from `@deepseek-ai/dsh-sci-agents` scanning the child session's web calls; a repeat is a verbatim re-issue, so the figure is a floor on redundancy (`clawsgo-analysis/CLAWSGO-SCHEDULING.md` §5 row 9).
- **The month is the host's month.** Both the subtitle and the 本月调用 tile count whatever the host treats as the current month, and this view neither offers a range picker nor states which boundary was used.
