# dsh-client-ui-auth

[English](README.md) | 中文

登录在浏览器一侧的部分：两步登录卡片、两个邮件落地页，以及侧边栏底部的账号行。它是 [`dsh-auth-gate`](../../auth/auth-gate/README.zh.md) 的客户端另一半，自身不做任何判断——这里的界面能被看到时，Host 早已拒绝过那个请求。

在不做认证的部署里挂载这一行是无害的。插件做的第一件事是在门的 `/auth` 通道上调用 `me`；没有挂载门的部署没有这条路由，调用在传输层就失败，此后整页的全部界面保持隐藏。

## 登录

卡片铺满外壳的 overlay 层并接收指针事件，因为在 Host 知道请求者是谁之前，它背后的应用无法使用。它在两种情况下出现：启动时的读取表明 cookie 没有认证到任何人，以及传输层报告某次 `/api` 调用被当作未认证拒绝。

登录分两步。邮箱地址与密码发往 `login.start`；得到 `2fa-required` 后，卡片询问 Host 发到邮箱的六位验证码，并发往 `login.verify`。成功后服务端装上会话 cookie，页面随即在新 cookie 下重新启动——此前每一个界面和两条事件流都是以"无人"的身份打开的，不重载就会让半个应用继续用它并不持有的凭据说话。

两种退出方式都在账号行里：**退出登录**调用 `logout`，结束这个浏览器的会话；**退出全部设备**调用 `logoutEverywhere`，结束该账号的全部会话。两者之后同样是页面重新启动。

## 邮件里的链接

门以其配置的 `baseUrl` 为基址发出绝对链接，本包负责这些链接指向的两个路径。`/reset-password?email=…&token=…` 打开新密码表单，并通过 `password.reset` 兑换令牌。`/verify-email?token=…` 通过 `email.verify` 兑换令牌，且只报告是否兑换成功。缺少令牌、或缺少重设所需地址的链接，会回落到普通登录，而不是半开一个提交不了的表单。

## 失败信息可以说到哪一步

门对密码错误、地址没有账号、账号被停用、验证码过期，一律回答同一个没有形状的 `failed`，使得登录表单无法被用来探查哪些邮箱有账号。本包在文案上保持这条性质：一句话覆盖上述全部情形，重设请求的回执写成"如果该地址有账号"，而不是一句确认。Host 归因于速率限制的拒绝显示为"请稍后再试"——绝不给出次数、期限或尝试总数。

每个提交在请求进行中都会被禁用并显示进度，因此一个步骤不会被发送两次。

## 401 接缝

`dsh-client-connection` 发布 `ctx.connection.authRequired`：一个自锁的可观察量，在 `/api` 首次得到 401 应答时翻转。传输层不对它做任何事——调用方看到的仍是一直以来的传输失败——本包是它唯一的读者。它翻转时，卡片会去问 Host `me`，而不是自行假定：这次拒绝可能与另一个标签页中已经成功的登录相竞争。

## 模型体验

无：登录界面在浏览器里渲染请求门给出的答案，任何地址、密码、验证码或会话事实都不会进入模型请求。

#### KV Cache 影响

无；本包不贡献任何请求内容，因此不存在可被失效的前缀。

## 已知限制与暂缓事项

- **凭据变更的代价是整页重启**——登录与两种退出都重载页面，而不是重新驱动外壳连接后的那套流程，因为对象层没有为"给活着的连接重新认证"留出接缝；否则事件流会继续用它们被打开时的那份凭据运行。
- **没有管理界面**——账号、用户组与规则属于 [`dsh-client-ui-settings-access`](../ui-settings-access/README.zh.md)；本包只覆盖已登录者对自己账号所做的事。
- **账号行给出的是一个地址，而不是会话清单**——`me` 报告账号及其所属用户组，门也不发布某个用户其余在线会话的列表，因此"退出全部设备"无法说明它结束了多少个。
- **非 HTTP 载体永远不会报告 401**——worker 预览通道自带 API 客户端，没有任何 HTTP 状态码到达这个锁存量，那里的登录界面只能靠启动时的读取打开。
