# @deepseek-ai/dsh-client-ui-sci-files

English | [中文](README.zh.md)

The Files mode of the details column: a project tree over a preview of one file, registered as the `files` entry of `conversation.details.mode` ([ui-conversation](../ui-conversation/README.md) owns the strip and the built-in `tool` inspector). The panel mounts the active mode alone, so this package draws and fetches nothing while another tab shows. Composing it out of cordis.yml removes the tab; a details column left with one mode renders no strip at all. Contract: the [slot system standard](../../../.agents/notes/implemented/architecture/2026-07-22-slot-type-chain-implementation.md).

The panel's own chrome sits above that split. The header names the selection from its path — an extension badge and the file name — and sizes it from the read the preview made, which is why an office document the runtime streams shows no size line rather than a guessed one. A segmented control switches between the rendered preview and the file's source; it stays inert for an image, a PDF, or opaque bytes, none of which have a source reading, and for a document no read produced bytes for. The preview stays mounted behind the source view, so switching back does not read the file again. Download assembles the bytes the preview already holds into a blob and hands it to the browser, releasing the object URL with the click — no second route, no second authorization. The card offers no close and no width control: the column's own header owns closing, and its width is the frame's fixed share — repeating either here was duplicate chrome. Under the header sits one chip per file the session produced, grouped by extension, so a report written three turns ago is one click away instead of a walk down the tree.

The tree is rooted at the session's project directory and lists one level per open directory, once, keeping what it read so reopening a directory costs nothing. Levels come from `workspace.listDirectory`, which carries the same session-cwd containment fence as the read, so both surfaces agree on what "inside the project" means. Each row is a directory to open, a file to preview, or an entry that is neither — a socket, device, or dangling symlink, shown inert because it has no bytes to read and no level to list. The gateway sends dotfiles and this client hides them, matching the workspace directory picker's default; a directory named `versions` carries a read-only tag because the sci workspace refuses edits inside it. A level is complete or absent: one past the deployment's entry cap fails with `too-many-entries` rather than arriving cut, and each of the seven listing error codes has its own sentence.

The preview dispatches on what the file is. A `.univer` unit is routed on the extension before any read happens — it is a SQLite container the Viewer streams from the Gateway, and the state route accepts no other extension. The exported office formats (`.xlsx`, `.docx`, `.pptx`) read as ordinary bytes instead: their preview states the size, offers the download, and names `univer_import` as the way to open them online — framing them dead-ended in a runtime-unavailable notice, since the state route refuses their extensions. Everything else is read whole through `workspace.readFile` (which refuses a file past the deployment's `readFileMaxBytes` cap rather than truncating it) and dispatched on the media type the host derived: Markdown renders as prose through `MarkdownText`, source and plain text as a highlighted `CodeBlock` under a size line, images as a data URL, and a PDF natively through pdf.js — each page a canvas styled like the rest of the panel (the browser plugin's own chrome and dark backdrop are gone), the first eight pages on selection and the rest behind a gesture that names the count. Bytes with no renderer state their size and that they cannot be shown. Each of the seven `workspace.readFile` error codes has its own sentence; an unrecognized code reads as an internal failure rather than disappearing.

`OfficeFrame` asks the office runtime's `/univer-api/state` for the document's Viewer target and Gateway liveness, then frames `mode=embedded&scope=trunk`. Editing is granted (`editable=true`) only while the Gateway is running, because an edit is a collaboration write with nothing behind it otherwise; a stopped Gateway frames the document read-only and says so. A runtime that does not answer — no office plugin composed, a Gateway that failed to start, an expired license — produces the stated reason, never an empty rectangle. One non-answer is only a race, so it is not stated at once: a host that has just restarted rejects the read with `SESSION_SCOPE_UNAVAILABLE` until it has attached the session, and that code alone is retried three times (after 0.8s, 1.6s, and 3.2s) before the frame reports anything; every other failure settles the read immediately, and the notice carries a Retry the user drives for a host slower than the whole span.

That answer is untyped JSON on a route no RPC schema covers, and its `viewerUrl` becomes an `<iframe src>`, which is script execution in this origin — so it is validated as the wire boundary it is. `trustedViewerUrl` accepts only a same-origin relative path under `/univer-gw/`: a `javascript:` or `data:` reference parses to an opaque origin, `//host` and any absolute URL to a foreign one, and `/univer-gw/../evil` normalizes out of the prefix, which is why the check reads the parsed pathname rather than the raw string. `gatewayRunning` must be the boolean `true`, never merely truthy, because it is what grants editing. `embeddedViewerUrl` repeats the source check and throws rather than assembling a target it cannot vouch for; the two callers are independent and the sink is worth two lines. The frame itself carries `sandbox="allow-scripts allow-same-origin allow-forms"` — the capabilities the Viewer needs and no others, notably not popups, top-level navigation, downloads, or modals.

Auto-locate has two halves that read the same fact. Which file shows is a pure derivation over the session's conversation snapshot: the newest settled `deliver_files`, `univer_export`, or `univer_new` call names it in its own arguments, so opening the tab lands on what was just made, its directories already open, and a reloaded session lands where the live one did. When to bring the column forward is necessarily live — a conversation-event Definition replays the whole window on every session load, and switching tabs from inside that fold would yank the panel open on every refresh — so the watcher follows the current session's assembled snapshot, takes its first reading as a baseline, and calls `ctx.layout.showDetailsMode('files')` only on a later change.

A row the user clicks pins the selection, recorded against the newest produced file at that moment. The pick outranks that state of the world and nothing else: the mode follows again the moment the session produces something newer, so a second delivery locates itself without making the first pick feel ignored. The store carries only that pin and the set of open directories; file bytes, listings, and office state are fetched per selection by the component that shows them.

`ctx.sciFiles` is the one gesture other plugins have for this mode: `locate(path)` pins the path exactly as a tree click does — recorded against what the session has produced right now, so a later delivery still locates itself — and then brings the column forward. It lands the pin whether or not the column has ever rendered, which is why the mode's store is created in `apply` instead of being declared at the registration seat: a chip clicked while the details column is closed must not lose its pin.

This package also takes the details column's `tool` mode body, registered at priority -10 so it shadows the built-in card-aware renderer; leaving this plugin out of the composition returns that renderer. The seat is the output body alone — the panel that owns it renders the call's arguments as its own Input section above it — so the sci reading is the call's identity over what came back. The tool's noun and its state sit on one line: running with a live stopwatch, or done/failed with the dispatch-to-settle duration when the call head is still in the window. Under it, the result text exactly as the model saw it, framed in the error color when the call failed and cut at 20,000 characters with the cut announced. There is no step timeline, because the wire carries a call and a result, not progress between them.

The `/client` exports are the plugin body (`apply`/`inject`), the `ISciFiles` service type, the two produced-file derivations (`locatedPath`, `allLocatedPaths`), and `toolDisplayName`. The last three cross the package boundary deliberately, as a stated exception to the client export discipline: the sci conversation lists the same produced paths as artifact chips and titles the same calls on its cards, and a second copy of either table would drift from this one. The components, the dispatch table, the path arithmetic, the store, and the watcher stay package-internal behind the slot registration.

## Model Experience

None, as this is a browser-side details-column mode whose Node half is an inert loader seat: it registers no tool, prompt section, or session event, and every byte it shows is read from the host on the user's gesture.

#### KV Cache effect

None; this package neither assembles nor sends a provider request.

## Known Limitations and Deferred Work

- **The mode's viewing state is one instance, not one per session.** The store is created in `apply` so `locate` can write to it before the first render, which means the pin and the open-directory set are shared across sessions. The pin carries the produced file it was made over, so switching to a session that produced something else releases it on the first render; the open directories genuinely persist. Per-session instances would need the service to queue writes until the column mounts.
- **Tool display names do not follow the locale.** `toolDisplayName` is a pure name table rather than a dictionary lookup, because its cross-package consumers title cards outside any locale seat. Tool nouns therefore stay Chinese in an English UI; every other string in this package goes through the `sci-files` dictionaries.
- **Taking the `tool` body takes it for every tool.** The seat is single-occupant, so the built-in terminal, read, diff, search, and web cards are absent from the details column while this plugin is composed. A per-tool sci card belongs in the keyed `tool.call.toolview` seat instead, which this package does not claim.
- **A level is read once per panel life.** Nothing invalidates a listing, so a file the agent writes into an already-open directory does not appear until the details column is reopened. The wire publishes no filesystem-change event to subscribe to; polling was rejected as a cost the panel would pay on every open directory forever.
- **Auto-locate reads call arguments, not results.** The wire carries a tool's model-facing result as rendered text, so the produced path comes from the call's own JSON. A `deliver_files` call whose last file was rejected therefore locates a path that never reached the user, and a delivery of several files locates only the last one named.
- **A collapse of a followed file's ancestor does not stick.** While the mode follows a produced file, the directories revealing it are held open on top of the user's own set; collapsing one of them re-opens on the next render. Pinning any file releases the hold.
- **The Viewer frame's sandbox bounds capability, not origin.** `allow-same-origin` is required — the collaboration client's WebSocket to the Gateway goes through this origin's `/univer-gw/ws` proxy and needs the session cookie that authorizes it, which an opaque origin would drop. Combined with `allow-scripts` that means a frame which does load can clear its own sandbox attribute, so the attribute constrains a well-behaved Viewer rather than containing a hostile one. What keeps a hostile document out is the source check on `viewerUrl`, in both `trustedViewerUrl` and `embeddedViewerUrl`. Containing a compromised Viewer bundle would need a separate origin for the proxy and a cookie scoped to it.
- **The office frame reports connection, not sync progress.** The header reads from `/univer-api/state` once per document; the Viewer publishes no in-frame sync signal this panel can subscribe to, so a collaboration session that drops after the frame loaded keeps reading as connected until the document is reselected.
