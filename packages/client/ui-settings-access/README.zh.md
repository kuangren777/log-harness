# dsh-client-ui-settings-access

[English](README.md) | 中文

[`dsh-auth`](../../auth/README.zh.md) 在浏览器一侧的管理界面：一个设置分区，覆盖账号、权限组、成员关系，以及每个组所带的规则。它是网关那九个 `auth.admin.*` 方法的客户端另一半，自身不做任何判断——这里显示的每一次拒绝都来自 Host。

在不做认证的部署里挂载这一行是无害的。分区做的第一件事是在请求门的 `/auth` 通道上调用 `me`；没有挂载门的部署没有这条路由，页面会说明这里没有可管理的对象，而不是摆出一堆用不了的表单。

## 隐藏这一页只是体贴，不是控制

分区对所有人注册。是否渲染表单，取决于门对 `me` 的回答：管理员得到这一页，其他人得到一段说明。这里没有任何东西构成安全边界——网关把九个方法全部标为 `admin` 策略行，无论浏览器画不画按钮，来自非管理员的调用一律拒绝。先问一句换来的是另外两件事：页面能解释自己，并且不会发出一个它已经知道会被拒的调用。

## 账号

名册就是全部账号，不过滤也不分页，因为接缝就是这样回答的。创建账号需要一个邮箱地址和一个初始密码；把这个密码交到本人手上是管理员的事，页面此后不会再显示它。**停用**阻止账号继续认证，**恢复**撤销它——被停用账号已有的登录会话不受影响，因为结束会话是接缝单独暴露的另一个决定。

## 权限组与成员

新建的组是空的。内置管理员组既不渲染重命名也不渲染删除，因为成为它的成员正是成为管理员的方式，接缝对这两个操作都会拒绝。成员关系整体保存：勾选一个账号提交的是该组的完整名册，Host 只会给此前不在组内的账号发出通知邮件。

## 规则，以及编辑器不让你误入的锁死

一条规则由域、模式、效果三部分组成。模式是精确名称，或以 `*` 结尾的前缀；域有技能、工具、`provider/model` 路由、设置命名空间四种。优先级为拒绝高于允许，都不匹配则拒绝。

陷阱在于某个域的**第一条**规则做了什么。没有任何规则涉及的域是完全开放的，而第一条涉及它的规则会把整个域变成白名单。于是单独一条 `deny secret-skill` 挡掉的不是一个技能，而是全部技能，且线格式本身对此只字不提。编辑器在三处回答这件事：

- **它补上兜底允许。** 为某个域添加第一条拒绝时，会同时加上一条 `allow *`，并说明它这么做了。于是"只挡一个"成为顺手的路径，而严格白名单只差删掉一行。
- **它说明剩下什么。** 某个域的规则若一个名称也不允许，会被点名警告，并说明哪个组将失去该域下的全部内容；被收窄为若干显式允许的域也会被提示，语气更轻。
- **它预览结果。** 对每个域，页面都会明确说出它是完全开放、除写明拒绝外开放、白名单，还是全部拒绝。对技能它更进一步解析真实清单：分区按当前会话读取 `skill.inventory`，列出成员能看到哪些技能、规则拒绝了哪些。预览按草稿计算，包含未保存的修改，因此后果在保存之前就可见。

管理员完全不受规则约束，所以预览会明说它算的不是正在看这一页的人。技能按会话的工作目录发现，因此没有打开会话时页面会说明这一点，而不是预览一份空清单。

## 模型体验

无：管理界面在浏览器里渲染认证接缝给出的答案，任何账号、用户组、规则或密码都不会进入模型请求。

#### KV Cache 影响

无；本包不贡献任何请求内容，因此不存在可被失效的前缀。

## 已知限制与暂缓事项

- **预览只解析技能**——其余三个域只报告受管或开放，而不逐名列出，因为页面没有一份按成员视角过滤过的工具、模型路由或设置命名空间清单。
- **规则只能增删，不能就地修改**——改一个模式意味着删掉这一行再加一次；编辑器没有就地编辑字段，在一个组只带少量规则时可以接受，规则上到几十条就不行了。
- **成员关系从组这一侧编辑**——没有"某个账号属于哪些组"的视图，因此把一个人在多个组之间挪动就是一个组一次保存。
- **保存被拒时显示接缝自己的文字**——地址重复、组名重复、id 不存在，都汇成表单上方的一行错误，而不是指向出问题的那个字段，尽管线协议里带着足以做到这一点的机器可读 `authCode`。
