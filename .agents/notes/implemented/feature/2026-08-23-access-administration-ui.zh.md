# Agent Note: 规则编辑器在锁死发生之前把它说出来

Status: implemented

[English](2026-08-23-access-administration-ui.md) | 中文

## 问题

[请求门](2026-08-23-auth-bootstrap-cli.zh.md)与[浏览器登录界面](2026-08-23-browser-login.zh.md)让一个部署可以做认证，网关也长出了九个 `auth.admin.*` 方法，覆盖账号、用户组、成员关系与权限规则。但浏览器里没有任何东西能够到它们：第一个管理员登录之后，要添加第二个账号就得离开产品。

管理界面难，不难在增删改查，而难在规则代数里那件任何表单都无法佯装无辜的事。没有任何规则涉及的域是完全开放的，而**第一条**涉及该域的规则会把整个域变成白名单：拒绝优先于允许，没有规则匹配即拒绝。于是管理员写下最自然的那一条——`deny secret-skill`——挡掉的并不是一个技能，而是该组的全部技能；而线格式、数据库、接缝都会默默接受它。这个错误一直看不见，直到某个成员来报告说产品是空的。

## 决定

`@deepseek-ai/dsh-client-ui-settings-access` 是 Web bundle 的一行，注册一个 `settings.section`（id `access`，order 30，排在所有"给自己配置产品"的分区之后）。它只通过那九个网关方法读写，也不改变任何语义：这个陷阱的解法完全落在编辑器做什么、说什么上。

### 三重防护，没有一重是语义改动

**补种。** 为某个域添加第一条规则、且这条规则是拒绝时，同时在旁边加上一条兜底允许，并明确说明它这么做了。于是"只挡一个"成为默认路径，而严格白名单只差删掉一行。补种出来的是一条普通规则，payload 里没有任何标记——不能为了一个浏览器上的便利，让 Host 去认识第二种规则。

**警告。** 一次按域的分析把草稿归为开放、除写明拒绝外开放、白名单、锁死四类。`locked` 点名该组，并说明它将失去该域下的全部内容；`allowlist` 说明所有未写明的名称都会被拒绝。`open-with-exceptions` 不出声——这正是"存在一条有效兜底允许时警告就消失"的原因。

判定 `locked` 不能只看"有没有允许规则"。`allow web_*` 配上 `deny web_*` 同样一个名称也不允许。分析改为向规则集自身提问：对每条允许规则，取该模式语言内的一个代表名——精确名称取其本身，通配前缀取前缀加一段打不出来的探针后缀——并在没有任何代表能够存活时判定该域锁死。探针是一个空格，而技能名、工具名、`provider/model` 路由、设置命名空间都不含空格，因此能覆盖探针的拒绝覆盖的是整个模式，而不是某一条写明的例外。

**预览。** 每个域的卡片说出自己的开放程度，对技能则由页面解析真实清单：按当前会话读取 `skill.inventory`，拆成成员能看到的与规则拒绝的两部分。它按草稿计算，因此后果在保存之前就在屏幕上。只有技能按名称解析，因为它是唯一一个页面能以成员视角读到的域；其余三个如实报告受管或开放，而不是猜。

### 版面承载代数，而前言承载不了

这个编辑器的第一版用一句话说明规则，然后渲染一个把四个域混在一起的扁平列表（`allow · Skill · foo`），开放程度与警告作为下方的散文段落。语义是按域的，版面不是，于是每一条按域的事实都只能再用文字复述一遍；读一个列表，等于要在脑子里同时装着四个域的状态。

现在的规则区是四张卡片，一域一张，四张始终都在。状态标记、规则小块、警告、补种提示，全部落在它们所属的那个域上；没有规则涉及的域渲染成一张安静的空卡片，而不是干脆不出现。于是为某个域添加第一条规则，会当着添加者的面改变那张卡片：标记从开放变为白名单或有例外的开放，下面那行文字随之改变，试算也开始拒绝一秒钟前还允许的名称。这个状态变化就是前言原本要教的那一课，`rulesIntro` 因此缩成一行。网格是 `auto-fit` 配 `minmax(280px, 1fr)`，因此在 640px 的手机形态下四张卡片自然落成一列。

每张卡片都带一个试算：填入一个候选名称，按当前草稿作答，并点出是哪条规则决定的。`probeName` 的判定本身取自 `memberPermits`，自己只补上"是哪一步优先级决定的"这一份报告，因此试算不可能与它上方的标记互相矛盾。"拒绝优先于允许"与"未命中即拒绝"写在这里，因为这里能亲手试出来——在一个同时带着 `allow *` 的域里输入被拒的名称，答案是"拒绝"，理由是"被拒绝规则 <pattern> 命中：拒绝优先于允许"。它也是本包里唯一能回答"没人为之写过规则的名称"的读法，而这恰是管理员真正会问的问题。

补种本身没有改变，但它的提示挪到了补种发生的那张卡片上，这也正是 `AccessState.seeded: boolean` 变成 `seededDomain: AccessDomain | undefined` 的原因。

### 预览需要不带绕过的答案，所以代数在浏览器里重写了一份

`dsh-auth` 的 `permits` 对管理员短路，这是对的。而编辑器问的是相反的问题——这个组的**普通**成员会看到什么——而且问的是只存在于未保存草稿里的规则，没有任何线方法能回答。于是 `rules.ts` 带了一份 `matchesPattern` / `evaluate` / `governs` 的第二实现，刻意不含绕过，并在模块里说明原因。这重复的是大约二十行纯函数；替代方案要么是客户端包 import 一个 Host 包（分层禁止），要么是为"评估假设规则"新增一个只有一个消费者的公开线方法。

### 隐藏分区只是外观，服务端的拒绝才是控制

分区对所有人注册，因为客户端 bundle 只构建一次，而部署是用 host 侧 overlay 选择启用认证的。它渲染什么由门对 `me` 的回答决定：管理员得到这一页，已登录的非管理员得到一段说明，`/auth` 通道没有路由的部署得到另一段说明，说这里没有可管理的对象。

这些都不是执行，README 与文案都这么写。网关把九个方法全部标为 `admin`，无论浏览器画不画按钮，来自非管理员的调用一律拒绝；一个把自己藏起来的页面安全性完全相同，只是更不诚实。先问 `me` 换来的是另外两件事：空状态能解释自己，并且界面绝不发出一个它已知会被拒的调用——单元测试也正是按这一点钉住的，因为"什么都不渲染"和"什么都不渲染且不出声"是两种行为。

### 成员关系整体保存，内置组没有删除控件

`members.set` 替换整份名册并报告哪些账号是新加入的，因此勾选一个账号提交的是整份列表，由 Host 决定给谁发信。内置管理员组既不渲染重命名也不渲染删除，因为接缝对两者都拒绝——控件是缺席而不是"存在但禁用"，因为不存在任何一种它能起作用的状态。

## 影响

`AdminGroupView`、`AdminRuleView`、`AdminUserView`、`GroupId`、`UserId` 现在经 `dsh-client-connection/client` 与 `dsh-api-remotes/client` 再导出。此前它们只能从 Host 包取到，而客户端插件不得指名 Host 包。

浏览器 journey 在同一个 host 上以两个不同账号登录——写下规则的管理员，以及随后发现被拒技能已从 Host 过滤过的清单中消失的成员。后半段才是整个改动的要点：管理页面描述的是一个决定，而它所描述的执行属于别处。

`dsh-client-ui-auth` 的"没有管理界面"这条限制现在指向本包，而不再指向产品之外。

## 备选方案

**改语义，让只有拒绝的域保持开放。** 直接否决。那会让一条拒绝自身无法撤销任何东西，也会让一份规则集的含义取决于它恰好包含哪些效果。代数是对的，缺的是可供性。

**拒绝保存会锁死某个域的规则集。** 否决：锁死一个域是合理需求，一个表达不了它的表单只会把管理员逼向 CLI 或数据库。把后果说清楚，就是恰当分量的帮助。

**把兜底允许做成复选框而不是自动补种。** 否决：在一张已经被填错的表单上再加一个复选框，只是又给了一次错过它的机会。补种让安全的读法成为默认发生的那个，而且这一行可删，所以什么也没被拿走。

**逐名预览每一个域。** 暂缓：管理员自己的工具、模型路由、设置命名空间清单是按**他**过滤的，要解析成员会看到什么，要么需要网关未提供的按域未过滤读取，要么需要一个"假设评估"方法。说出受管或开放既真实又便宜；README 记下了这个缺口。

**对非管理员直接隐藏分区，而不是渲染空状态。** 否决：它看起来像一个权限模型而其实不是，并且教会读者"缺席即拒绝"——而在某个 bundle 发出一行部署并未授权的行时，这个结论第一次就是错的。

**就地编辑规则。** 暂缓：每组只有少量规则时，删掉再加一次的表面积小于一个自带脏状态追踪的可编辑列表。记为限制，因为规则上到几十条时这个判断就不成立了。
