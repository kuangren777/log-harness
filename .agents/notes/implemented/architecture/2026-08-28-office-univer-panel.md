# Agent Note: The office document panel — dsh-univer-office vendored behind a same-origin proxy

Status: implemented

English | [中文](2026-08-28-office-univer-panel.zh.md)

## Problem

The model's only path to an office document was the `docx`/`pptx`/`xlsx` skills: text-level authoring with no in-app rendering. The details column showed one thing regardless — `ui-conversation`'s tool-call inspector — so a produced spreadsheet or slide deck reached the user as a delivered file and nothing else; nobody could see or edit it inside the session. Two authoring paths for the same document class also meant the model could pick either one, so protecting a richer surface would not have helped: the unprotected skills would still be there to bypass it.

## Decision

`packages/office/univer/` vendors [`dsh-univer-office`](../../../../docs/office-univer-upstream.md) at fork commit `97e348cf44b1eb57d5025dbf7155c8148d72683d` as `@deepseek-ai/dsh-office-univer`, full-fidelity: `src/host`, `src/client`, `src/shared`, and `skills/` are copied source compiled against this tree, and the Gateway executable, Viewer, render machine, and content worker are prebuilt bytes fetched from the pinned `dsh-univer-office@0.2.10` npm release, verified against a recorded sha512 and extracted as a git-ignored `artifacts/` (~143 MB) at build time. The package's own dependencies resolve nine Univer insider packages from `insider-npm-registry.univer.work` through three scoped-registry lines in the repository root `.npmrc`.

A browser on the harness origin cannot reach the Gateway's own loopback port, so `gateway-proxy.ts` puts it behind `/univer-gw` (prefix-stripped, the Viewer document and its chunks) and `/uf` (verbatim, the file content route and its WebSocket upgrade, bridged socket-to-socket). Every route runs the same browser-trust check the RPC channel applies to `/api` — `ctx.connection.isTrustedRequest` — and answers 403 when it refuses. The hop to the Gateway withholds `cookie`, `authorization`, `proxy-authorization`, `forwarded`, and every `x-forwarded-*` header outbound, because the Gateway is an unauthenticated loopback service; `set-cookie` is dropped on the way back so it cannot set cookies on the harness origin. Upstream targets are built from the parsed pathname, never a slice of the raw request target, so a path that leaves the prefix under normalization or carries an encoded traversal segment is refused with 400. Configurable timeouts bound every hop: `gatewayStartupTimeoutMs` for a cold start, `gatewayRequestTimeoutMs`/`gatewayMutationTimeoutMs` for Gateway HTTP calls, and `proxyTimeoutMs` for one proxied browser request or handshake.

`sci-profile` keeps the plane split it already states: the host row `office-univer` runs the Gateway and publishes the `univer` service with `tools: false, skills: false`, and each preset mounts `@deepseek-ai/dsh-office-univer/tools` over that shared service, naming `disabledTools: [univer_screenshot, univer_lint]` because the dsh image ships no headless Chromium. The package's own bundled `univer_*` skills stay unpublished; the skill vault serves them as the protected built-in tier through `sci-skills`, and the three retired `docx`/`pptx`/`xlsx` skills moved to `skills-retired/` so office documents have one authoring path.

The details column became a mode ring — `conversation.details.mode`, a `list` slot `ui-conversation` renders as a tab strip, with `ILayout.showDetailsMode`/`registerDetailsModeSelector` letting any plugin switch the column to its own mode without importing `ui-conversation` — and `ui-sci-files` registers the `files` entry over two new cwd-fenced RPCs, `workspace.readFile` and `workspace.listDirectory`. Its `OfficeFrame` asks `/univer-api/state` for the document's Viewer target and Gateway liveness, then frames `mode=embedded&scope=trunk&editable=<gatewayRunning>` — editing is granted only while the Gateway answers, because an edit is a collaboration write with nothing behind it otherwise. That `viewerUrl` becomes an `<iframe src>`, so it is validated as the wire boundary it is: `trustedViewerUrl` and `embeddedViewerUrl` each accept only a same-origin relative path under `/univer-gw/`, and the frame carries `sandbox="allow-scripts allow-same-origin allow-forms"` — the capabilities the Viewer needs and no others.

For the panel and the model's `univer_*` tools to see the same bytes, `sci-gate` calls Dormice's `POST /acquireSandbox` for the tenant's sandbox id before `createVmContainer` and binds `/var/lib/dormice/mnt/<id>:/home/user:rw` into the VM; a slug that was ever used keeps its Dormice sandbox name through a tombstone table, so deleting and recreating a tenant does not orphan or collide sandbox mounts.

The package keeps `Apache-2.0` in its own `license` field; the nine unlicensed Univer insider packages it depends on are recorded in `gen-third-party-notices.ts`'s `UNIVER_PRERELEASE_PACKAGES` as an owner-authorized distribution decision for internal testing only — the notices still record their terms as "no license declared," and a production release needs Univer's terms confirmed before it can redistribute `artifacts/` or those packages.

## Alternatives considered

- **iframe the upstream Viewer cross-origin.** Rejected: the Viewer's collaboration client needs the session's cookie-scoped authorization, which an opaque cross-origin frame drops; browser CSP would also need to allow a foreign origin, and the collaboration WebSocket cannot reach a same-origin proxy from a cross-origin frame.
- **Keep the `docx`/`pptx`/`xlsx` skills alongside the `univer_*` tools.** Rejected: two authoring paths for the same document class let the model pick the one the panel does not track, so the panel's investment would not pay off for documents made the other way. The three skills retired to `skills-retired/`.
- **Register `univer_*` on the host row.** Rejected by the plane-split rule this profile already states: a host row publishes services and registries shared across agents, while model-facing tools are a preset's own composition — the disabled-tool set differs per deployment need, not per shared service, and a service published from a row both presets mount would collide the moment the second preset mounted it.
- **Poll the workspace tree for freshness instead of an explicit invalidation signal.** Rejected, per `ui-sci-files`'s Known Limitations: the wire publishes no filesystem-change event, and polling would cost the panel a request on every open directory for the life of the panel; a level is read once and refreshes only when the details column reopens.

## Consequences

Building this package needs outbound network access, both to the insider registry for the nine Univer dependencies and to npm for the ~143 MB artifact fetch; a checkout that skips `pnpm run fetch-artifacts` has no Gateway to start. `disabledTools` withholds `univer_screenshot` and `univer_lint` in every current deployment, so no deployment offers rendered-page or layout-lint checks until a host provisions Chromium and drops the two names from its config. The unlicensed-package decision is scoped to internal testing; a public release gate must confirm Univer's terms before it can ship `artifacts/` or the nine insider packages more broadly. The VM-side Dormice bind is required, not incidental: a VM created before a gate carried this wiring has no `/home/user` mount, and the design's error handling names the resulting gap (`WORKSPACE_NOT_MOUNTED`) as something a gate retag fixes rather than the panel or tools working around it.
