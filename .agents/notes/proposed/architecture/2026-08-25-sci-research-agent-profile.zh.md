# Agent Note: 架在 dsh 扩展点之上的科研智能体 profile

Status: proposed

[English](2026-08-25-sci-research-agent-profile.md) | 中文

## 问题

一个被研究过的科研 agent 平台（存档于 `ClawsGO-System/`）把它全部的产品行为都通过服务端 prompt 拼装来交付：常驻的逐轮 reminder、以 prompt 片段表达的两个商业档位、一份会话启动时的 skill 名册、从 shell 输出里解析出来的 stdout sentinel，以及只以散文形式陈述的文件系统交付约定。它零 hook、零插件、零自定义 agent 人格，因为它的运行时是一个它自己无法修改 CLI 的受管沙箱。

这个约束造成了三个它自己的审计都记录在案的缺陷。所有权规则（「只有 `render.py` 能写 figure」「绝不要碰 `versions/`」）没有任何强制力，合规与否全凭模型选择。档位门禁（tier gating）（「不要在 Balanced 模式下扇出」）是一句请求，而不是限制。写死在档位 prompt 里的一条运行时断言——「Workflow 完成通知在这个环境里永远不会到达」——逐渐过时，先后被六次已送达的通知证伪，却没有任何机制把它下线，让模型徒劳地轮询。

dsh 对这三者都有真正的扩展点。在这里照搬纯 prompt 设计，会把行为和缺陷一起带进来。

## 提议

把产品组合成架在 `dsh-sci` bundle 与 `packages/sci/` 下诸包之上的 `sci` profile，把每个纯 prompt 机制映射到强制执行它的类型化扩展点上：

- 常驻 reminder 落成 `ctx.systemPrompt.context()` 条目，按每次 assembly 去重并带版本，而不是逐字重新追加到每条用户消息末尾。
- 两个档位落成两个 agent preset（`sci-balanced`、`sci-cluster`）。均衡档直接不挂扇出工具行；既有的 preset 选择器就是档位选择器，因此无需新增 UI。
- 「先声明计划再扇出」落成一道 `tools/pre-execute` guard：在本会话的声明工具成功之前拒绝 workflow 工具，用一道门禁取代 prompt 层面的指令。
- workspace 交付约定落成一道覆盖已挂载文件工具的 `tools/pre-execute` 策略：`versions/` 仅追加，交付限定在交付目录内，靠门禁而不是散文强制。它不能用 `fs/write-intent` / `fs/edit-intent`：那是单槽 waterfall，已经被 `dsh-fs-observation-policy` 占用，而本层还需要保留它的先读后写 guard。删除在文件 seam 里根本没有对应动词，因此拦住它的是沙箱自身的所有权划分。
- stdout sentinel 被去掉。它唯一的优点是能嵌进 shell 控制流；取而代之的是一等公民的 `deliver_files` 工具，带经过校验的 schema 和渲染出的结果。
- 那条过时的通知断言不会被搬过来。dsh 的 workflow 工具会阻塞父级轮次直到运行结算完毕，它描述的那种情况在这里根本不存在。与之配套的 `resumeFromRunId` 恢复机制出于同样的理由被去掉：dsh 没有 workflow 恢复能力，prompt 不能承诺运行时并不具备的能力。subagent 工具在 continuable 模式下确实会送达完成通知，因此运行时章节陈述这两个事实，而不是写一条一刀切的规则。

Skill 迁移为 bundle 自己 skill 根目录下的普通 skill 目录。有工作台支撑的格式（`.paper`、`.sciplot`、`.canvas`）保留各自的文件约定，但降级为普通文件交付，因为被研究平台的前端不在存档范围内，超出本提议范围。

## 考虑过的替代方案

**照搬纯 prompt 设计。** 这是被研究平台已经证明可行的做法，也无需任何扩展点。不予采纳：它会把该平台自己的审计记录下来的三个缺陷一并带入——一条过时且无机制下线的运行时断言、一个管理 skill 已被撤下的约定目录、一条带逃逸条款且实测合规率为零的记忆规则。这里对应的规则都是门禁，一条断言运行时事实的 prompt 必须配一条校验它的 invariant。

**全部强制执行，不保留任何解释性散文。** 更小也更无歧义。不予采纳：档位门禁的价值不只在于拒绝——被研究平台的均衡档段落说明了用户选了什么、上限为何存在、它保护的是谁的预算，以及合法的退出路径是什么；理解边界的模型不会伪造能力，也不会悄悄降级。门禁让规则成立，散文让拒绝可被理解。

**用一个带运行时开关的档位，而不是两个 preset。** 这样能在对话中途切换档位。不予采纳：preset 是按 id 挂载一次的常驻组合，因此不同档位的工具 catalog 本身就不同——这正是均衡档上限真实而非纸面约束的原因。代价是升档意味着开新会话，因此升档路径是以旧会话为种子创建新会话，而不是原地修改。

## 验收标准

上面每个机制都落在点名的扩展点上，并配一个测试证明门禁拒绝了被研究平台只是劝阻的调用：均衡档会话无法触达扇出工具，没有已声明计划的扇出被拒绝，写入 `versions/` 先后被工具层和沙箱所有权拒绝，交付目录之外的交付被拒绝，运行未签名二进制变成一个授权问题。每个包的 README 都点名它替代的机制以及变了什么。五份无密钥 snapshot 记录模型可见的拒绝结果，回归会以 transcript（文本记录）diff 的形式现身。

## 风险

门禁会拒绝一些原本能成功的调用，因此被研究平台靠无视自己的散文完成的任务，现在可能会明显失败；这是预期之中的，但也意味着本层第一批真实工作负载正是过严规则暴露出来的地方。沙箱所有权划分是任何绕过工具层、经由 shell 逃逸的最后一道防线，它依赖镜像构建而不是本仓库里的代码——一个没构建这道防线的镜像会静默丢失 `versions/` 的保证，同时所有测试仍然全绿。而且 prompt 章节仍可能与它描述的运行时逐渐脱节：invariant 伴生检查的是本层拥有的那些关系，不是每一句话。

## 后果

原本只是建议的行为变成了强制执行，会拒绝被研究系统只是劝阻的调用。档位归属变成会话开始时就固定的组合事实，而不是逐轮的 prompt 片段，因此会话无法在对话中途切换档位，除非开一个新会话。
