# Agent Note：以磁盘上的 `refs.bib` 为权威的按项目引用池

Status: proposed

[English](2026-08-31-sci-citations.md) | 中文

## Problem

`sci` 画像能找到文献（`literature_search`）也能记住文献（`sci-library`），但没有任何东西把这两者接到正在写的稿子上。由此产生三个后果，而且三个都是无声的。

写综述的模型拿不到 citekey，于是自己编一个。`\cite{zhao2015}` 指向一个参考文献里没有定义的 key，排版出来是 `[?]`，读者没法把它和拼写错误区分开。`sci-manifest` 的 `.paper` kind 没有 references 字段（`sci-manifest/src/kinds.ts:9-46`），`sci-paper/SKILL.md:43` 只说了 citekey 必须稳定——所以引用真正住在 `papers/<slug>/src/refs.bib` 里，而 harness 里没有任何东西读它或写它。

没有东西告诉用户哪些引用是真正承重的。「被引用 N 次」不是某个声称写过一段话的轮次能断言的，它必须从文件里读出来。没有这个数，一条早早加进来却从没用上的条目，和整个论证赖以成立的那条，看起来一模一样。

没有东西把四个索引一致认可的文献，和只在某篇预印本里出现过一次的区分开。行为不变式 #2（`00-Architecture/04-behavioral-invariants.md:8`）要求正文里的引用是真的而不是编的，而画像手里没有可据以行动的按文献信号。

## Proposal

一个 `packages/sci/sci-citations` 宿主包，发布 `ctx.sciCitations`（Remote 命名空间 `sci.citations`）、`citations_add` 与 `citations_list` 两个工具，以及 order 113 的 prompt 章节 `tool:citations`。

**磁盘上的参考文献是权威，用户的决定则无处再生。** 一条引用记录分成两半。书目那一半——标题、作者、年份、期刊、DOI、arXiv id——和正文引用次数 `uses` 都来自文件，随时可以重读：`rescan` 解析每个论文包的 `refs.bib`，并通过模型自己的 `read` 工具用的那个 `ctx.fs` 缝隙扫描项目的 `.md` 与 `.tex`。另一半——用户把条目归进的分组、写下的备注、手动设的隔离——没有第二个出处，所以合并规则更新前一半、绝不碰后一半。这正是让这个存储域成为便利存储而非投影的原因，而且它写在 `spec.ts` 里，不留作默契。

**写入是按字节保守的。** `upsertBibtexEntry` 只替换它要改写的那个 citekey 所占的那一段，其余情况追加，所以一份满是注释、`@string` 宏和自有排版的手写文件，能在模型往里写一条之后原样存活。解析器是刻意部分覆盖、也刻意大声的：读不了的块会变成一条带文件与行号的 `parseErrors`，因为「少一条但看得见原因」的池，胜过「无声地短了一截」的池。

**置信是算出来的。** 一个关于信号的纯函数：来源一致程度、有无年份、有无期刊、是不是只有 arXiv 预印本，以及按对数缩放的引用数。不调模型、不走网络、不看时钟——所以这个数可以存在记录上、可以作为理由而不是意见展示给用户，任何客户端都能算出一模一样的结果。知识库状态是人的判断而不是信号，所以它在最后收口，而不是喂回公式里。

**隔离下限是单向的，而它就是这个包的运行时不变式。** 低于 70 的条目自动被扣住；高于阈值时这个标记纯粹是某个人的决定。有四条路径会写这个标记（`add`、`rescan`、移出 `quarantine` 分组的 `move`、以及来自 patch 的 `update`），所以 `./invariant` 在 `domain/changed` 上断言：任何落库的、分数低于阈值的记录都不会被放行。它之所以重要，是因为这个标记正是同时在三个面上——prompt、工具输出、视图——把弱文献挡在稿子外面的东西。

**两个工具都不问模型自己在哪个项目里。** 会话本来就坐在某个项目里，所以 slug 由它在 `projectRoot` 之下的工作目录推断；不在任何项目里的会话得到的是一条点名了它该待在什么目录形态下的拒绝，而不是猜测。在这里猜，会把一条引用归进另一篇稿子的参考文献——而 citekey 稳定性约定存在的意义，正是防止这种损害。

## Alternatives considered

**把参考文献存进 `.paper` manifest 而不是 `refs.bib`。** 否决：LaTeX 读的是 `refs.bib`，所以 manifest 会成为一份会漂移的副本，而构建无论如何还是用文件。让文件成为权威，就不再有「哪一份是对的」这个问题。

**让模型用 `write` 工具自己写 `refs.bib`。** 否决：这把生成 key、去重和元数据解析都放进了模型脑子里，而编造出来的 citekey 正是从那里来的。走工具这条路，才让返回的 citekey 是一个事实而不是一句声称。

**用模型调用来打置信分。** 否决：用户没法核对的分数，是披着数字外衣的意见。算术版本可以逐行审计，而且每条记录的成本为零。

**rescan 时重算每一条的置信。** 否决：来自索引的记录带着 `refs.bib` 从来没有过的信号——尤其是 `citedBy`——照着文件重算会在每次扫描时把它压低。只有来源仅有文件的记录才重算。

**让 `update({ quarantined: false })` 能放行任何记录。** 否决：这个标记的文档定义就是「自动规则」与「人的决定」的析取，而只有后一半是谁能放下的。放行一条 30 分的记录，会让它同时在所有地方读作已核实。请求在规则允许的范围内被执行，返回的记录也如实这么写。

**把扫描到的文件数持久化。** 否决：它是某一次扫描恰好走过的数量，按一下重新扫描就能恢复，而且拿它没有任何可做的事。为这样一个数字建第三张表，不值得那次迁移。

## Acceptance criteria

- `citations_add` 经 `ctx.get('sciLiterature')` 解析 DOI，索引里没有的 DOI 直接拒绝而不是生成一个指向虚无的 key，把条目写进该项目的 `refs.bib`，并返回 citekey；`citations_list` 用真实计数渲染引用池并标出被隔离的条目。
- 两个工具都从会话工作目录推断项目，不在任何项目里时点名 `<projectRoot>/<项目>/` 并拒绝。
- `rescan` 收进只有文件知道的 citekey，在项目的 `.md` 与 `.tex` 里统计 `\cite{}` / `\citep{}` / `\citet{}` / `` `[key]` `` / `[key]`，并且不碰分组、备注和手设的隔离。
- 读不了的 `refs.bib` 块通过 `parseErrors` 连同文件与行号一起报告，它周围能读的条目照常载入。
- 经过每一条写入路径，落库的 `sci_citation` 记录中都不存在分数低于 70 而 `quarantined: false` 的。
- `packages/sci/sci-citations/src` 达成逐文件 100% 覆盖率，一个跑在真实项目树上的真实 Loader 组合测试，以及一个能回放的 `citations_add` + `citations_list` 无密钥快照。

## Risks

**手写的参考文献比任何解析器覆盖的都杂。** 读取器只保证常见的 `@type{key, field = {…} | "…" | 裸值,}` 形态加嵌套大括号。其余一切以 `parseErrors` 条目而不是失败的形式浮出来，这让池仍然可用，但也意味着文件形态特殊的项目看到的引用比它实际有的少。缓解手段就是错误列表本身：视图能精确显示哪一块被跳过、在哪一行。

**参考文献只归一个论文包。** `add` 写进列目录顺序上的第一个论文包。一个项目里两篇引用不同文献的稿子，需要 `rescan` 加人工拆分。按论文包分池是更大的模型改动，不在本次提案里。

**两张表不可重建。** 从浏览器视图做的改动没有会话日志可回放，所以丢掉存储介质就丢掉分组、备注和手设的隔离。书目那一半在 `refs.bib` 里活着、靠 `rescan` 回来，这限制了损失范围但并没有消除它。

**正文里的 `[n]` 不会链到引用池。** `ui-primitives` 只解析行内代码形式的 mention，所以读者会期待的「渲染出来的引用」与「引用池视图」之间的连接目前并不存在。这是一条已知限制而不是回归，能补上它的那道缝隙不属于本次改动。
